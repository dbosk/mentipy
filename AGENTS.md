# Mentipy Repository Guide

## Source of truth

- This is a literate noweb project. Edit `*.nw` files in `src/mentipy/` and `doc/`; do not hand-edit generated `*.py` or `*.tex` files.
- Generated artifacts are intentionally untracked: `src/.gitignore` ignores `*.py` and `*.tex`, `tests/.gitignore` ignores generated test files, and `doc/.gitignore` ignores woven/build outputs.
- After changing a module `.nw` file, regenerate it from the matching subdirectory with `make <module>.py` and, if documentation changed, `make <module>.tex`.

## Build and test commands

- Full project build: `make` at the repo root. This runs `compile`, builds `doc/mentipy.pdf`, and then runs tests.
- Compile package outputs only: `make -C src/mentipy all`
- Run all tests: `make test` or `make -C tests test`
- Focused test file: `poetry run pytest tests/unit/test_<module>.py -q`
- Regenerate one test file after changing `src/mentipy/<module>.nw`: `make -C tests unit/test_<module>.py`
- Weave the manual without building the PDF: `make -C doc mentipy.tex`
- Build the manual PDF: `make -C doc mentipy.pdf`

## Repo layout

- `src/mentipy/*.nw`: real implementation sources.
- `src/mentipy/mentipy.nw`: package facade; re-exports the public API from the smaller modules.
- `src/mentipy/questions.nw`: frozen question models and canonical hashing input.
- `src/mentipy/store.nw`: config loading, persistent JSON store, stable prefix resolution.
- `src/mentipy/venv.nw`: local virtualenv creation, package installation, and activation snippets.
- `src/mentipy/latex.nw`: PythonTeX-facing LaTeX helpers; handles registration and QR generation side effects.
- `src/mentipy/server.nw`: standard-library threaded HTTP server and HTML results/forms.
- `src/mentipy/cli.nw`: Typer CLI; thin wrapper over store/server/LaTeX helpers.
- `src/mentipy/public.nw`: public exposure helpers for `mentipy serve` (UPnP and SSH reverse tunnels).
- `src/mentipy/qr.nw`: QR generation via `segno`.
- `src/mentipy/sty.nw`: the companion LaTeX package `mentipy.sty` (`\mentipybasedir`, `\mentipyinput`); tangled by an explicit `mentipy.sty: sty.nw` rule (a `mentipy.sty.nw` name would clash with the facade's weave), shipped as wheel package data, installed by `mentipy sty [--install]`. Its integration test compiles a real book+deck and is skipped without `pdflatex`/`pythontex`.
- `tests/Makefile`: auto-discovers `<<test [[module.py]]>>` chunks in `src/**/*.nw` and tangles them into `tests/unit/test_*.py`.

## Non-obvious workflow constraints

- Tests live inside the module `.nw` files. Add or update tests there, then regenerate `tests/unit/test_*.py` via `make -C tests ...`.
- The default tangling rule runs `black` on generated Python (`makefiles/noweb.mk` sets `NOWEB_PYCODEFMT=black`). If tangling changes formatting, treat the `.nw` file as the editable source and re-run the tangle instead of editing generated Python.
- The manual uses PythonTeX with `poetry run python3` (`doc/Makefile`). If documentation examples depend on runtime code, prefer verifying with `make -C doc mentipy.tex` or `mentipy.pdf` rather than assuming plain LaTeX is enough.
- PythonTeX caches per-block stdout in `doc/pythontex-files-*/`. Adding or removing `pycode`/`pyblock` blocks shifts block numbering and can leave stale cached outputs bound to the wrong `\saveprintpythontex{...}` names, which usually surfaces as a "Missing $ inserted" error on an underscore identifier in some unrelated block. Run `make -C doc clean` before `make -C doc mentipy.pdf` whenever you insert or delete a Python block in `doc/mentipy.nw`.
- `make test` depends on `compile`, so root-level tests regenerate package outputs before running `pytest`.
- Runtime state file `mentipy.json` is ignored at the repo root. Do not commit it.

## Cross-cutting touchpoints when adding a question type or helper

A new question type or top-level helper has to land in several places beyond its own module `.nw` file. The unit tests do not catch the user-facing ones, so it is easy to ship a half-wired feature. The checklist:

- **Package facade** `src/mentipy/mentipy.nw`: add the new symbol to the `<<imports>>` chunk and to `__all__`, and extend `test_package_facade_reexports_the_public_api`.
- **CLI render subcommand** in `src/mentipy/cli.nw`: add `@render_cli.command("<kebab-name>")` alongside `render_mc`/`render_open`/`render_scale`, import the LaTeX helper with an `as render_<x>_question` alias, and add one thin test that asserts the flags reach the stored question (mirror `test_render_open_threads_the_fence_option_into_the_question`).
- **`mentipy latex` reference text** in `cli.nw`: extend `_latex_reference()` with the new helper signature *and* update the matching `test_latex_command_prints_the_reference_and_all_config_keys` assertions, otherwise the test will pin the old wording.
- **Intro chapter** `doc/mentipy.nw`: add a `\subsection{...}` under "Choosing an Authoring Path" with a paired PythonTeX example, the matching `mentipy render ...` CLI command, and a `\ltnote{...}`. Also extend the two excerpt-filter helpers `render_help_excerpt` and `latex_pydoc_excerpt` so the discovery section lists the new name.
- **A new shared per-question flag** (like `next`, `results`, `lock`, or the `context` keyword) touches the `Question` base class in `questions.nw` (field, `to_dict()`, `canonical_dict()`, `_shared_fields()`, the explicit `to_dict()` expectations in its tests), `PinImageQuestion.from_image_bytes`, all seven wrappers in `latex.nw` plus the `HELPER_FACTORIES` test, all seven `render` subcommands in `cli.nw` plus a `QUESTION_<X>_OPTION`, the `_latex_reference()` signatures and "Per-question keyword arguments" text with its test, and the manual.
- **A new `mentipy serve` flag** touches `serve` and `_serve_publicly` in `cli.nw`, and `serve()`, `create_server()` and `_build_handler()` in `server.nw`; the CLI tests spy on `serve_http` with `**kwargs`, so add a thin test per branch.

## Design principles to preserve

- **Identity vs presentation in question hashes.** Question hashes must depend only on the input contract (the prompt, the character or option set). `OpenQuestion.fence` historically still enters the hash when set, but newer question types should keep visualisation fields out of identity via a separate `canonical_dict()` method that `question_hash()` consults. `WordCloudQuestion` is the precedent: two visualisations of the same prompt share a hash, a URL prefix, and an answer pool.
- **Web-only context: premises are identity, presentation is not.** `Question.context` is a tuple of `ContextSnippet` (shown: Pygments language, `None` prose, or `"latex"` with pandoc HTML cached in `html`) and `ContextDownload` (offered: bytes in the store's content-addressed sidecar via `Store.save_image`, served at `/<prefix>/context/<index>` as an attachment through the respondent gate; the index, not the digest, so a prefix can only serve its own files). The answer form (`_render_form()` in `server.nw` assembles every kind: `_render_prompt()`, the kind's `_render_inputs()` with Submit, then `_render_context()`, so a long program never separates a question from its options) and the results page (`_render_results()`: aggregate stats and visualisation, then the context, then the per-answer lists, i.e. open answers and `_render_pin_comments()`) show it; the slide never does. Its premises enter the canonical hash like `PinTextQuestion.content`: each item's `canonical_dict()` is its tag plus the snippet `text` or the download `sha256`, while label, language, cached `html`, filename and size are presentation. `Question._context_identity()` adds them and is `{}` without context, so context-free hashes are unchanged; the overrides that build their identity from scratch (word cloud, both pins) must splice it in, which `test_question_hash_depends_on_the_context_across_question_types` checks for every kind. Editing the program therefore mints a new prefix and QR code. `to_dict()` writes every context key, so a presentation-only change (a removed label), the only context change that still reaches refresh-on-merge, clears the stored value. `test_questions_without_context_keep_their_earlier_hashes` pins one pre-context hash per kind. File routes (`/image`, `/context/<i>`) call `_resolve_for_respondent(..., follow=False)` so a skipped question shows the waiting page instead of redirecting to another question's file at the same suffix. Authoring resolves items in `latex._resolve_context()` against the helper's own store: `file_snippet(path, name=...)` (whole file or a class/function by dotted name via `ast`, decorators included, read through `resolve_path`), `file_download(path)` (a pending item read at registration), plain strings as prose. CLI: `--context`/`--context-download` on every `render` subcommand via `_render_common_kwargs`.
- **The `Question` base class owns the shared fields and serialisation entry points.** All question dataclasses subclass `Question` (`questions.nw`), which declares the prompt `text` plus the keyword-only `next` and tri-state `results` flags, writes `kind`/`text`/flags around each subclass's `_own_dict()` in `to_dict()`, provides the default `canonical_dict()` subtraction, and extracts the shared fields in `_shared_fields()` during rebuild. The two pin types share a further `PinQuestion` base carrying the keyword-only `max_pins`/`allow_comment` contract (validated in its `__post_init__`; subclasses must chain `super().__post_init__()`); dispatch sites use `isinstance(q, PinQuestion)` — the old `PIN_QUESTIONS` tuple is gone. A new question type subclasses one of these bases, implements `_own_dict()` and `_from_dict()`, joins the `QUESTION_KINDS` registry, and overrides `canonical_dict()` only when identity is narrower than persistence. Keep shared default-valued fields keyword-only — positional defaults on a base would break subclass positional construction.
- **Inline code in prompts and options.** Prompts (every kind) and MC/ranking options mark code with backtick pairs (Markdown-like, `` `len(xs)` ``); `questions.inline_code_spans()` is the one reading of that rule (a span is a single backtick, one or more non-backticks, a single backtick, neither delimiter touching another backtick, so LaTeX ``quotes'' stay literal; anything else is literal). `latex._render_inline()` typesets spans as `\texttt` (slide and notes, via `_render_question_content`) and `server._render_inline()` as `<code>` (forms, `_page` headings, index, ambiguous-prefix list, bar labels, mode callout, ranking stats), each escaping every piece first; `_page` titles use `_plain_inline()` (backticks dropped). The backticks are part of the stored text, so hashes of text without them are unaffected. Code spans on the slide use `LATEX_CODE_ESCAPES` (breaks T1 ligatures, `\textquotesingle`, control spaces); `LATEX_ESCAPES` turns `"` into `\string"` because babel swedish/ngerman make it a shorthand (not `\textquotedbl`, fatal under OT1). Pairing is left-to-right, so a stray backtick before a code span steals it; authors should use `'` and typographic quotes. LaTeX prompts (raw on the slide, pandoc for the web) are not supported yet: #54.
- **The results page opens on the server session.** `store.results(window=...)` accepts `RESULTS_WINDOWS = ("session", "hour", "day", "all")`; `"session"` cuts at the `server_started` timestamp that `create_server()` writes into the store via `Store.mark_server_start()` (a top-level key in `mentipy.json`, overwritten on every start, the only server state in the store; lecture progress stays in memory), and falls back to `"all"` when no server has started or the value is not a timestamp (`_session_start`). Any server start on the store, a second server on another port included, moves the cut for every reader; `create_server()` marks after the bind and closes the socket if the mark fails. The HTML results page (lecturer and respondents) defaults to `RESULTS_PAGE_WINDOW = "session"` because reused questions share a hash and an answer pool, and a sliding hour would empty a question asked before the break. `mentipy view`/`watch` (both modes) default to the same window (`--window`, validated against `RESULTS_WINDOWS`, named in the heading by `_responses_line()`); `watch` detects new open answers by timestamp (`_answers_after`), not by count, since a restart shrinks the window. Compare stored timestamps only through `store.parse_timestamp()` (`isoformat` drops zero microseconds, so strings misorder). `results.json`, `store.results()` and `mentipy export` keep `"all"`. Unknown values fall back to the caller's default. Tests that read the default page must record their answers after the test server starts. A non-default window is carried by `_window_query()` through the lecturer's Previous/Next links and the Skip/Reopen forms and redirects.
- **Per-question results visibility is a tri-state.** `results=None` defers to `mentipy serve --results`; `True`/`False` override it per question at both server decision points (post-submit redirect and the GET results gate, resolved by `_results_public()` in `server.nw`). Admin/local access is checked independently and must never be blocked by the override.
- **Lecture progress is session state, never store state.** `mentipy serve` paces respondents by default (`--no-lock` disables it): a question is open to respondents only after an admin GET of its `/results` page this server run, or when it has `lock=False` and the question before it in the deck is open (transitively; a `lock=False` head is open). "Before it in the deck" is the store's full registration order as returned by `Store.all_questions()` (orphans included), deliberately *not* the navigation row's live suffix: re-registering one existing question (a re-run PythonTeX block, a `mentipy render` in a terminal) moves it to the end of the store, and pacing on the full order guarantees that can never open a question the lecturer has not reached. The `LectureProgress` tracker lives in the `_build_handler()` closure in `server.nw`, holds no store reference and takes the deck rows as data, so a GET never mutates `mentipy.json` and a restart re-locks everything (the lecturer's refreshing results tab reopens the current question). Set semantics: skipped questions stay locked. Only the routes that reveal a question are gated (form, image, results, via `_resolve_for_respondent()`); POST and `/thanks` are deliberately not. `/active` redirects to the most recently *newly* opened question (first-open-wins, so a stale refreshing tab cannot move it) and shows a self-refreshing waiting page before any opening or when that question has left the store; the tracker records openings even under `--no-lock` so `/active` keeps working. A locked question the lecturer has moved past (a skip) 303-redirects respondents to the active question at the same suffix; the waiting page itself never links to `/active`. The lecturer's results-page nav row (chosen by `_admin_allowed()`, not the loopback address, via `_render_results(admin=...)`; it floats at the bottom of the window through CSS alone, `.question-nav:has(.skip-form)` with `position: sticky`) has a Skip button (`POST /<prefix>/skip`, admin-only) that calls `LectureProgress.close()` and redirects to the next results page; `close` relies on `_opened` being an insertion-ordered dict so `/active` falls back to the previous still-open opening. Skips are sticky (`_skipped` set): `open()` ignores skipped hashes so a refreshing second results tab cannot undo a skip, a skipped question stops the `lock=False` walk as locked, the index labels it `skipped`, and only `POST /<prefix>/reopen` (a Reopen button in a banner on the skipped question's results page) undoes it. The respondent's Next links to `/<prefix>/next`, which decides at click time: behind the lecturer (`moved_past`) → active question, otherwise → next in order (never `/active`, which would bounce a fast respondent back); admin and `--no-lock` get the plain next. The admin index labels each question active/open/locked with the same rule. Because `/active` follows admin requests, admin is now a write capability: a tunnel that makes students look local lets them steer the room. A bare `mentipy watch` (no PREFIX; chosen over an `--active` flag) follows the lecture from outside the server: each tick `_active_state()` in `cli.nw` sends `GET /active` with `http.client` (never following redirects, never sending the admin token, so it works under `--public ssh` and opens nothing) to `--server` (default `http://localhost:<mentipy.port>`, or the `mentipy.host` address when it is not a wildcard; validated at startup by `_http_url_parts()`, with a warning for an ignored path, query, fragment or userinfo); a 303 `Location`'s first segment is the prefix, a 200 carrying `X-Mentipy-Active: waiting` (set on the `/active` waiting page in `server.nw`) is the waiting page (status and header are read, never the page text, which #62 may translate; a 200 without the header counts as not-Mentipy), anything else or a connection error (`ACTIVE_REQUEST_TIMEOUT`) is a retrying message. On a change of that state `_switch_to()` clears and starts a fresh `_QuestionWatcher` for the prefix, resolved in watch's own store (a prefix missing there is retried every tick); otherwise it refreshes the current one. `watch PREFIX` uses the same `_QuestionWatcher`, and `PREFIX` with `--server` is rejected.
- **Base directory: files resolve, LaTeX paths do not.** Every file Mentipy reads or writes on the author's behalf (store path at `Store` construction, QR writes, pin images, `write_snippet`) goes through `resolve_path()` in `store.nw`; every path emitted into LaTeX (`\input` of sidecars, the sidecar's `\includegraphics`, pin image paths) stays as the author wrote it, because the `import` package's `\input@path`/`\Ginput@path` find it in the deck. A relative base is anchored at `_ANCHOR_DIR`, the cwd when `mentipy.store` was first imported (the sty imports Mentipy while the preamble loads), matching didactic's `\runbasedir`. `None`/`""` means off and must stay byte-for-byte the old cwd behaviour. `regenerate_qrs` reads the include path back from the existing sidecar (`sidecar_include_path`) rather than recomputing it from serve's cwd. The sty syncs Python only at PythonTeX code starts and `\mentipybasedir`, only on change (Beamer re-reads), default session only.
- **`Store.register()` is refresh-on-merge.** When the canonical hash already exists, `register` merges `question.to_dict()` over the stored entry rather than returning early, so editing presentation in a slide source and recompiling takes effect on the next results request. The merge preserves auxiliary keys like `qr_targets` (set by `remember_qr_target`). Do not regress this back to early-return-on-known-hash without thinking through the lecturer's iteration loop.

## Packaging and runtime facts

- Python requirement is `>=3.10,<4.0` (`pyproject.toml`).
- The console entrypoint is `mentipy = "mentipy.cli:main"`.
- Defaults and config keys live in `src/mentipy/store.nw`; both CLI and LaTeX helpers read settings from there.
- Optional public exposure support is packaged as `mentipy[public]`, which installs `miniupnpc` for the UPnP mode; SSH mode stays stdlib-only.
- Optional denser word-cloud SVG rendering is packaged as `mentipy[wordcloud]`; `render="svg"` falls back to the built-in SVG layout when that extra is not installed.
- `MENTIPY_CONFIG` overrides the config file location for tests and local runs.
- Pin-image questions store the lecturer's image bytes content-addressed in a sidecar directory next to the store file (`mentipy.json` → `mentipy-images/<sha256>`, gitignored); the same sidecar holds context-download bytes. The server serves images at `/<prefix>/image` unconditionally — `allow_images` only guards respondent-chosen images in open answers.
- Pin-text questions with `language="latex"` run pandoc once at registration (`latex.pin_text`) and cache the HTML in the question dict; pandoc is an optional system dependency, and a missing one degrades to highlighted source with a warning. Unit tests monkeypatch the subprocess call, so CI never needs pandoc.
- `mentipy.sty` is package data (`pyproject.toml` includes `src/mentipy/*.sty`); it is generated and gitignored like the `.py` files.
- The pin form's click-capture script in `server.nw` is the only JavaScript in the project; it interpolates only integer/boolean literals, never user text.

## Commit hygiene for this repo

- In this repo, committing generated `src/mentipy/*.py`, `src/mentipy/*.tex`, `tests/unit/*.py`, or `doc/mentipy.tex` is almost certainly wrong. Commit the corresponding `.nw` sources instead.
